# Config reference

Every key of a served repo's `.github/governor.json`. Generated by `node scripts/export-config-schema.mjs` from `configSchema` in [dispatch/repo-config.mjs](../dispatch/repo-config.mjs), the schema governor reads the file with, so edit a description there, not here. [The JSON Schema](../schema/governor.schema.json) an editor reads holds the same descriptions. [Serving a repo](serving-a-repo.md) says how a repo opts in.

A section turns its feature on unless it sets `"enabled": false`, and a feature with no section is off. A prompt is text, or `{ "file": "<path>" }`. The file holding the text: a path in the repo, from its root, read from the default branch beside the config file. A skill file's frontmatter is dropped.

This page covers the shape only. Governor also refuses a file that breaks a rule across keys, such as a claim label that is also a ready label, and the config check runs every rule.

## `$schema`

The URL of this file's JSON Schema, for an editor to describe and check each key. Governor ignores it. Use the schema at the commit the config check is pinned to, and bump both together.

## `environment`

The claude.ai cloud environment the repo's sessions start in: its name as `/remote-env` lists it, or its ID. A public repo should use the name.

## `trust`

`{ "start": [ … ], "auto": [ … ], "task": [ … ], "relay": [ … ], "review": [ … ] }`: whose GitHub text governor acts on, by `author_association`. `start` is who may set work going, by readying a ticket or writing a summons, default `OWNER`, `MEMBER` and `COLLABORATOR`, which a repo may narrow and never widen. `auto` is whose issues and PRs governor sets going by itself, default `OWNER`, `MEMBER` and `COLLABORATOR`. `task` is whose issue or PR may become work when a person readies it or summons a session on it, default the same three. `relay` is whose text may reach a running session, default those three and `BOT`. `review` is whose pull requests the PR review reads, default the three.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `trust.start` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE`, `BOT` |  | Who may set work going, by `author_association`: whose ready label counts, and whose summons starts a session. Default `OWNER`, `MEMBER` and `COLLABORATOR`. A repo may narrow it, never widen it: any other value, and `BOT`, is refused. |
| `trust.auto` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE`, `BOT` |  | Whose issues and PRs governor sets going by itself, with no person choosing the ticket, by `author_association`: a spec session or owner message when a ticket's wait ends or its blocker closes, a periodic's issue counts and listings, and the conflicts check. Default `OWNER`, `MEMBER` and `COLLABORATOR`, narrowed to fit `task`, `relay` and `review` where the file sets them. `BOT` is refused. |
| `trust.task` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE`, `BOT` |  | Whose issue or PR may become work when a person sets it going, by `author_association`: pickup starts a ready ticket, and a summons starts a session, only where its author is listed. Default `OWNER`, `MEMBER` and `COLLABORATOR`, narrowed to fit `relay` and `review` where the file sets them. `BOT` is refused. |
| `trust.relay` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE`, `BOT` |  | Whose text may reach a session that is already running, by `author_association`, with `BOT` for any account GitHub marks as a bot: their comments and reviews, and a session link or `governor:subscribe` line in the body of an issue or PR they open. An event such as a label, a close or a push is judged by the author of the issue or PR it is on. Default `OWNER`, `MEMBER`, `COLLABORATOR` and `BOT`, less any of the first three a `trust.review` the file sets leaves out. Governor's own App is never judged. |
| `trust.review` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE`, `BOT` |  | Whose pull requests governor's PR review reads, by `author_association`, with `BOT` for any account GitHub marks as a bot. A pull request by an author it leaves out gets a `neutral` `governor` check, and a person merges it. Dependabot's pull requests are read by `prReview.dependabot` whatever it says. Default `OWNER`, `MEMBER` and `COLLABORATOR`. |

## `workflows`

| Key | Type | Default | What it holds |
|---|---|---|---|
| `workflows.ci` | string |  | The CI workflow's file, under `.github/workflows/`. A red run of it tells the sessions of the merges it may blame, and the PR review waits for its run at a PR's head. Without it, no run is CI. |

## `pickup`

A session per ready ticket, picked up on its label, on the close of its last open blocker, and on the sweep at the interval `sweepHours` sets. Its labels serve the features that read them, so a file turning on `unblocked`, `waits`, `prReview` or `issueReviews` has this section, with `"enabled": false` if pickup is to stay off.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `pickup.enabled` | boolean |  | Whether the feature is on. Default on: only `false` turns it off, and then the section needs none of its required settings. |
| `pickup.ready` | list of string |  | Required when pickup, `unblocked`, `waits`, `prReview` or `issueReviews` is on. Every label a ready ticket carries. |
| `pickup.claim` | string |  | Required when pickup, `unblocked`, `waits`, `prReview` or `issueReviews` is on. The label governor claims a ticket with before its session starts. It is created in a repo that lacks it. A ticket carrying it is never picked up. |
| `pickup.claimRemoves` | list of string | `[]` | The ready labels the claim takes off, and a failed launch puts back. Default none. |
| `pickup.exclude` | list of string | `["type: prd"]` | Labels that keep a ticket out: a ticket carrying any of them is never picked up, and a blocker's close starts no session for it. It cannot name a ready label. Default `["type: prd"]`. A hold label, one that marks a ticket as needing a person or staying not ready (`mode: human`, say), belongs here, or a blocker's close starts a session to rewrite that ticket's spec. |
| `pickup.sweepHours` | whole number, at least 1 |  | How many whole hours the hourly fire leaves between two sweeps of the repo's ready tickets, at least one. Default one, which sweeps at every fire. |
| `pickup.prompt` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a pickup session's opening prompt, below `Pickup #N 'title'`. It may name the facts {issue}, {repo} and {claim}, which governor writes in. The text, or { "file": "<path>" }. |

## `subscribeMessages`

Messages to sessions subscribed by a `governor:subscribe` line, and to an issue's filer. On a claimed ticket, a comment, a close and a reopen also reach the sessions building it, and each message names the ticket's spec owner and builders. Governor's own comments on an issue reach no session through it: the turn that posts one tells the roles itself. A session hears a `deployed:` label only through a subscribe line for `deploys`.

| Key | Type | Default | What it holds |

| `subscribeMessages.prompt` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a CI or deploy notice's ask to a subscriber. It may name no fact. The text, or { "file": "<path>" }. |

## `unblocked`

What a blocker's close does to a ticket that is not ready to pick up: a comment when the blocker closed as not planned, a message to a claimed ticket's session, and the spec work on a not-ready ticket. The session whose link ends the ticket's body owns it and is asked to rewrite its own spec; a fresh session rewrites it only where the body names no session or that session is archived, so nobody takes a ticket from its owner.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `unblocked.enabled` | boolean |  | Whether the feature is on. Default on: only `false` turns it off, and then the section needs none of its required settings. |
| `unblocked.prompts` | object (`ready`, `spec`, `ownerSpec`, `claimed`, `notPlanned`) |  | Replacement wording for the instruction in each kind of message the feature sends, keyed by kind: `ready`, `spec`, `ownerSpec`, `claimed`, `notPlanned`. |
| `unblocked.prompts.ready` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a ready ticket's ask, below its pickup prompt and the facts of its blocker's close. It may name no fact. The text, or { "file": "<path>" }. |
| `unblocked.prompts.spec` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a not-ready ticket's spec session's ask, below the facts of its blocker's close. It may name the facts {issue}, {ready} and {claim}, which governor writes in. The text, or { "file": "<path>" }. |
| `unblocked.prompts.ownerSpec` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of the ask to a not-ready ticket's owner, the session its body names, below the facts of its blocker's close. It may name the facts {issue}, {ready} and {claim}, which governor writes in. The text, or { "file": "<path>" }. |
| `unblocked.prompts.claimed` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a claimed ticket's session's ask, below the facts of its blocker's close. It may name the fact {issue}, which governor writes in. The text, or { "file": "<path>" }. |
| `unblocked.prompts.notPlanned` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of the ask in the comment, and message, when a ticket's blocker closed as not planned. It may name no fact. The text, or { "file": "<path>" }. |

## `deployMessages`

A shipping job, or a red deploy, tells the sessions of the merges it shipped. Governor sees a deploy only where the deploy workflow marks it. The shipping job's name ends ` · deployed: <target>`, a middle dot with one space each side, with `at <sha>`, the whole 40-character commit, before the dot when the job ships a commit other than the run's head. Mark only the job whose success means the change is live, never a rollback. The workflow also sets a top-level `TICKET_LABEL_PATHS` env, which picks the shipped PRs that hear of it: `all`, `trigger` for those that changed a file under its `on.push.paths`, or globs, one per line. The first marked run only sets the baseline.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `deployMessages.enabled` | boolean |  | Whether the feature is on. Default on: only `false` turns it off, and then the section needs none of its required settings. |
| `deployMessages.triage` | list of string | `[]` | The deploy targets whose failure starts one fresh session, rather than messages to the sessions of the merges it shipped. Default none. |
| `deployMessages.tags` | object of string, keyed by name | `{}` | The tag each deploy target's deploy moves, keyed by target, which deploy messages name. Default none. |
| `deployMessages.deployedLabels` | boolean |  | Whether a shipping job labels the tickets it shipped `deployed: <target>`, and comments on each ticket the first time it gets that label, for people to read; the shipping job messages each such ticket's spec owner and builders itself. Default false. |
| `deployMessages.prompts` | object (`triage`, `green`, `greenMany`, `red`, `redMany`) |  | Replacement wording for the instruction in each kind of message the feature sends, keyed by kind: `triage`, `green`, `greenMany`, `red`, `redMany`. |
| `deployMessages.prompts.triage` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a failed `triage` target's fresh session. It may name no fact. The text, or { "file": "<path>" }. |
| `deployMessages.prompts.green` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a green deploy's ask, for one PR. It may name the facts {pr} and {target}, which governor writes in. The text, or { "file": "<path>" }. |
| `deployMessages.prompts.greenMany` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a green deploy's ask, for several PRs. It may name the facts {pr} and {target}, which governor writes in. The text, or { "file": "<path>" }. |
| `deployMessages.prompts.red` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a red deploy's ask, for one PR. It may name the fact {pr}, which governor writes in. The text, or { "file": "<path>" }. |
| `deployMessages.prompts.redMany` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a red deploy's ask, for several PRs. It may name the fact {pr}, which governor writes in. The text, or { "file": "<path>" }. |

## `prReview`

The PR review: its prompt, and the lists it checks a PR against. Needs `prompt` when on.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `prReview.enabled` | boolean |  | Whether the feature is on. Default on: only `false` turns it off, and then the section needs none of its required settings. |
| `prReview.prompt` | text, or `{ "file": "<path>" }` |  | Required when on. The review model's system prompt, after governor's fixed frame and before a suffix naming what the code decided: the text, or { "file": "<path>" }. |

| `prReview.humanOnly[].glob` | string, required |  | The paths a PR may not change without a person, as a glob. |
| `prReview.humanOnly[].reason` | string, required |  | Why a person must see a change to these paths, which the review says. |
| `prReview.humanOnly[].unless` | list of string | `[]` | Labels that waive the wait when every ticket the PR closes carries one and passes the review's ticket checks. They waive nothing for a PR from a session governor started. Default none. |
| `prReview.tickets` | object (`require`, `forbid`) | `{"require":[],"forbid":[]}` | The label rules every ticket the PR closes must meet: `require` and `forbid`. |
| `prReview.tickets.require` | list of object (`labels`, `unless`) | `[]` | Rules each ticket the PR closes meets by carrying one of the rule's labels, unless it carries one of its `unless` labels. Default none. |
| `prReview.tickets.require[].labels` | list of string, required |  | The labels the rule is about. |
| `prReview.tickets.require[].unless` | list of string | `[]` | Labels that waive the rule for a ticket carrying one of them. Default none. |
| `prReview.tickets.forbid` | list of object (`labels`, `unless`) | `[]` | Rules each ticket the PR closes meets by carrying none of the rule's labels, unless it carries one of its `unless` labels. Default none. |
| `prReview.tickets.forbid[].labels` | list of string, required |  | The labels the rule is about. |
| `prReview.tickets.forbid[].unless` | list of string | `[]` | Labels that waive the rule for a ticket carrying one of them. Default none. |
| `prReview.quote` | list of string | `[]` | Globs of changed files the review model reads whole, at the merge base and at the head. Only a modified file is quoted: one added, removed or renamed waits for a person. A `!` entry takes a path back out. Default none. |
| `prReview.decides` | list of string | `[]` | Labels of a ticket that may decide a quoted file's change: its body's first line, `Constraint now lives at <path>, …`, names the files it decides, which then pass unread. Default none. |
| `prReview.dependabot` | list of string | `[]` | Globs of the manifests a Dependabot PR may change and pass with no model. Default none. |
| `prReview.requireChecks` | list of string, or object (`name`, `app`) | `[]` | Checks the review treats as required, beside any the default branch requires on GitHub: a name, which a check run from any App or a commit status context meets, or `{ "name", "app" }`, which only that App's check run of the name meets. One red on the PR's head fails the review for a push; one not finished, or not posted, holds the review with `governor` in progress until it ends. A name GitHub also requires counts once, and the review's own `governor` check is left out. Default none. |
| `prReview.requireChecks[].name` | string, required |  | The check run's name. |
| `prReview.requireChecks[].app` | string, required |  | The slug of the GitHub App that must post it, such as `github-actions` or `github-code-scanning`: lowercase letters, digits and hyphens, the last part of its `github.com/apps/<slug>` page. A run of the name from any other App, and a commit status of the name, does not count. |
| `prReview.waitForCi` | boolean | `true` | Whether the review waits for the `workflows.ci` run at the PR's head: one red fails it for a push, one not finished, or none at the head, holds it with `governor` in progress. Set it false where the CI workflow does not run on pull requests, such as one that runs only on a push to the default branch; the review then reads no workflow runs, and still reads the required checks and `requireChecks`. A red CI run on the default branch still drives `ciMessages`. Default true. |
| `prReview.merge` | boolean | `true` | Whether a pass merges the PR. With false, a pass posts its comment and a success check, and the owner merges. Default true. |

| `waits.prompts` | object (`spec`, `ownerSpec`) |  | Replacement wording for the instruction in each kind of message the feature sends, keyed by kind: `spec`, `ownerSpec`. |
| `waits.prompts.spec` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of a not-ready ticket's spec session's ask, below the facts of its ended wait. It may name the facts {issue}, {ready} and {claim}, which governor writes in. The text, or { "file": "<path>" }. |
| `waits.prompts.ownerSpec` | text, or `{ "file": "<path>" }` |  | Replaces the default wording of the ask to a not-ready ticket's owner, the session its body names, below the facts of its ended wait. Governor sends this once per session. Default false: every hold is only logged. |

## `sessionRules`

The three rules every session in the repo follows: sign what you post, only an owner edits a body or pushes to a PR's branch, and comment on what you do not own. Every session governor starts reads them in the lines governor adds to its opening prompt, in place of the signing line. Sessions a person starts read them in the block the repo copies into its `CLAUDE.md`, or the file `file` names, and the config check warns where that block is missing or old. With `signOff` on as well, an issue a session owns holds its ask to sign off only where it carries a ready label or the claim label, since signing off gives it up. Governor also offers an issue nobody owns to a session that signs a comment on it, confirms a take by a session that ends its body with its own link, and, with `subscribeMessages` on, writes a live owner's link back after another session moves it. With `prMessages` on, it does the same for a PR's session link. Whatever this switch says, governor searches the login's live sessions in the repo for the author of a session's post that names no session, and for whoever edited an issue's body, so neither is sent its own change back. Under this switch, the author is told once to sign its post, and a session that edited another session's issue is told once to comment instead.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `sessionRules.enabled` | boolean |  | Whether the feature is on. Default on: only `false` turns it off, and then the section needs none of its required settings. |
| `sessionRules.file` | string |  | The file that carries governor's session rules block, a path from the repo's root, which the config check reads at a pull request's head, and governor's hourly fire on the default branch. Default `CLAUDE.md` at the root. |

## `issueReviews`

The issue reviews: `reviews`, each keyed by its name, with its selector `when`, the labels each of its `conclusions` adds, and optionally its own `prompt` and checks and labels per label (`byLabel`), and `enabled`. Each comments on a ticket it selects whether it passes, waits for an edit, or waits for a person, and applies that conclusion's labels. Governor runs them where the file has this section, unless `enabled` is `false`. Pickup meets a review only through its labels: list a review's `success` label in `pickup.ready` where a ticket should wait for the review to pass it, its `neutral` labels in `pickup.exclude`, and the claim label in its `when.exclude`.

| Key | Type | Default | What it holds |
|---|---|---|---|
| `issueReviews.enabled` | boolean |  | Whether governor runs the reviews. Default on: only `false` turns them off. |
| `issueReviews.reviews` | object of object (`when`, `conclusions`, `prompt`, `byLabel`), keyed by name |  | The issue reviews, each keyed by its name: lower-case letters, digits and hyphens. The name goes into every comment and marker the review writes, so renaming a review starts its rounds afresh. Reviews run in the order of their keys. At least one when on. |
| `issueReviews.reviews.<name>.when` | object (`labels`, `exclude`, `by`) | `{}` | The review's selector: the labels and authors a ticket must meet. Default every issue its default `by` lets in. |
| `issueReviews.reviews.<name>.when.labels` | list of string |  | Labels the ticket must carry, every one of them, in any case. Default none. |
| `issueReviews.reviews.<name>.when.exclude` | list of string |  | Labels the ticket must not carry, any of them, in any case. Default none. |
| `issueReviews.reviews.<name>.when.by` | list of any of `OWNER`, `MEMBER`, `COLLABORATOR`, `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `MANNEQUIN`, `NONE` |  | Who may have opened the ticket, as GitHub's `author_association` values. Default `OWNER`, `MEMBER` and `COLLABORATOR`. The repo's `trust.review` bounds every review. |
| `issueReviews.reviews.<name>.conclusions` | object (`success`, `failure`, `neutral`) | `{"success":[],"failure":[],"neutral":[]}` | The labels each conclusion adds: `success`, `failure` and `neutral`, each a list, each none when unset. Each run adds its conclusion's labels and removes the ones the other two name, and touches no other label. Each label starts with the review's name, a colon and a space, such as `triage: build` for a review named `triage`, in any case, so a review never adds or removes a label a person uses. A label appears under one conclusion of one review. A review whose `by`, within `trust.review`, reaches beyond `trust.auto` names no ready label. No conclusion names a label a `byLabel` entry matches on, a label the review's own `when.labels` or `when.exclude` names, or `pickup.claim`. |
| `issueReviews.reviews.<name>.conclusions.success` | list of string | `[]` | The labels a `success` adds: the ticket passes. Default none. |
| `issueReviews.reviews.<name>.conclusions.failure` | list of string | `[]` | The labels a `failure` adds: the ticket waits for an edit by whoever filed it. Default none. |
| `issueReviews.reviews.<name>.conclusions.neutral` | list of string | `[]` | The labels a `neutral` adds: the ticket waits for a person. Default none. |
| `issueReviews.reviews.<name>.prompt` | text, or `{ "file": "<path>" }` |  | The review's own prompt, after governor's fixed frame: the text, or { "file": "<path>" }. Default governor's own checklist. |
| `issueReviews.reviews.<name>.byLabel` | list of object (`labels`, `prompt`, `conclusions`) |  | Checks and labels per label, each entry matched by label. A ticket gets the review's prompt and then each matching entry's, in list order; one matching none gets the review's alone. For each conclusion, the labels come from the first matching entry that names it, and otherwise from `conclusions`. |
| `issueReviews.reviews.<name>.byLabel[].labels` | list of string, required |  | The labels that match a ticket carrying any of them, in any case. At least one. |
| `issueReviews.reviews.<name>.byLabel[].prompt` | text, or `{ "file": "<path>" }` |  | Checks a matching ticket gets after the review's own prompt: the text, or { "file": "<path>" }. Default none. |
| `issueReviews.reviews.<name>.byLabel[].conclusions` | object (`success`, `failure`, `neutral`) |  | The conclusions whose labels this entry overrides, each a list, each label starting with the review's name, a colon and a space. A conclusion it leaves out takes its labels from an entry later in the list that matches, or from the review's `conclusions`. |
| `issueReviews.reviews.<name>.byLabel[].conclusions.success` | list of string |  | The labels a `success` adds on a matching ticket, in place of the review's. |
| `issueReviews.reviews.<name>.byLabel[].conclusions.failure` | list of string |  | The labels a `failure` adds on a matching ticket, in place of the review's. |
| `issueReviews.reviews.<name>.byLabel[].conclusions.neutral` | list of string |  | The labels a `neutral` adds on a matching ticket, in place of the review's. |
