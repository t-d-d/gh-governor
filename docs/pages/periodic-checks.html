gh-governor · how a periodic's limits are checked

One check, two callers

A periodic starts a session when one of its limits is reached: a count of merges that touch given paths, a count of issues, or a time limit. An event never carries a count. It only queues a check, and the check reads the count afresh from GitHub. This page follows fires, turns and checks through four cases.

Proposed in PRD #772. Not built yet.

A limit

A periodic has a prompt and a when. It fires when any one limit is reached.

"Turn review": {
  "prompt": { "file": "…" },
  "when": {
    "merges": { "count": 10,
      "paths": ["dispatch/**"] },
    "days": 30
  }
}

Each limit names a measure. A measure says which events wake a check, and how to read what happened since the last fire.

The check

One planner reads a repo's due periodics and hands its launches to launchPlan, the path every session starts through. Two things run it:

  • An event's own fire. A merge, or an issue opened or closed, queues a periodics fire for the repo.
  • The hourly sweep. It reads every limit, and it is where a time limit comes due.
  • Nothing else. A held fire waits for one of those two.

Rules

  • No running total. Every count is read from GitHub since the periodic's last fire, so a lost webhook only delays a fire.
  • A periodic never overlaps itself. A fire that comes due while its last session is in the middle of a turn is held until the next check.
  • A time limit is a plain timer. It runs from the last fire, and it starts a session even where nothing was counted.
  • A record moves only after a launch. A failed launch leaves the periodic due.
Start

A fire. P is a periodics check, X a merge's conflict check, S the hourly sweep. A delivery, or an HTTP answer. A call, a write or an answer. A read. One merge the limit counts.

What the animation does not show

  • The starter and the login. A task is started when a fire waits and none runs, and each turn restores the claude.ai login. The fire lane page follows both.
  • The minimum gap. A periodic with gapHours never fires inside that many hours of its last run. A count reached there fires on the first check after it.
  • What a check reads. A check that finds nothing due makes one list read of merged pull requests, and one files read for the merge that just landed. It stores no total.
  • A repo with no limit on merges. The receiver queues a periodics fire only where the repo's file has a limit the event wakes.
  • A new periodic. With no record, the check writes now as the baseline and starts nothing. Its window opens there.
  • Issues and labels. issuesOpened and issuesClosed are checked the same way. A limit with labels is also checked when an issue's label changes.
  • Other fires. A turn does much more than this. Only the fires a merge and the schedule queue are drawn.
