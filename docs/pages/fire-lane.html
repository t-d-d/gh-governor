gh-governor · how fires run

One queue, one reader

Governor starts and steers Claude Code cloud sessions for GitHub repos. Everything it acts on, such as a PR comment, a review or a CI result, becomes a fire. Each fire runs as one turn inside a short-lived AWS Fargate task. Every fire waits on one queue, the lane, and one task reads it, one turn at a time. This page follows fires along that lane.

The lane

Every producer sends to one FIFO queue, governor-fires.fifo, in one message group. The webhook receiver sends GitHub's deliveries, hook calls and the two-hourly pickup. A turn sends the unblocked fires it queues, and scripts/run-turn.mjs sends a fire by hand.

The dispatcher task, dispatch/lane.mjs on Fargate, is the lane's only reader. Once started, it takes fires until the lane has been empty for 60 seconds, so a burst pays one cold start.

Constraints

  • One claude.ai login. Every turn refreshes it, and a refresh replaces the token. Two turns at once leave one of them with a dead login, so only one turn may run at a time.
  • A task, not a Lambda. The Claude CLI needs a terminal, and Lambda has none.
  • Scale to zero. With no work, nothing runs and nothing costs.
  • No lost fires. GitHub does not resend a failed delivery by itself, so the receiver puts a fire on the lane before it answers.

The starter

The governor-starter Lambda holds no fires. Each call asks two questions: does a fire wait on the lane, and does a dispatcher task run? It calls RunTask only when a fire waits and none runs. Otherwise it does nothing.

Three things call it: the receiver after it queues fires, every task's stop event, and a backstop schedule every minute.

Start

A fire. M is a message, R a review, C an issue closing, U an unblocked fire. A GitHub delivery, or an HTTP answer. A call to the starter, or a stop event. It carries no fire. The starter checking the queue or ECS. The login, restored or written back.

Limits the animation does not show

  • Thirty minutes a task. A task stops taking fires 30 minutes after it starts and leaves the rest to a fresh task, so a deploy's new image is picked up. A turn started before then runs to its end.
  • Eighteen minutes a turn. Each turn has its own deadline. Past it the task logs dispatch-failed with reason deadline and exits. Fires behind that turn were never received, so they wait on the lane for the next task.
  • Between fires. The task clears the CLI's state under HOME and its working directories, so one turn leaves nothing for the next.
  • The dead-letter queue. A fire the task's parser refuses goes to governor-fires-dead.fifo at once. A turn that fails is logged and not retried.
  • Fires that do not call the starter. A turn that queues unblocked fires, and scripts/run-turn.mjs run by hand, leave their fires on the lane. The running task takes them, or the backstop starts a task within a minute.
  • A failed call from the receiver. The receiver calls the starter asynchronously. If that call fails, it is logged and the delivery still answers 202. The fire is already on the lane for the backstop to find.
